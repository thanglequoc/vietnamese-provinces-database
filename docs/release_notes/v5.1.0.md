Bản release v5.1.0 bổ sung bảng metadata `vn_provinces_metadata` (phiên bản dataset, nghị định mới nhất, thời điểm tạo) cho toàn bộ các định dạng, giúp ứng dụng xác định phiên bản bộ dữ liệu đang cài đặt; đồng thời cập nhật Quảng Ninh trở thành thành phố theo Nghị quyết 36/2026/QH16 và dọn dẹp các tệp trùng lặp còn sót lại.

## ✨ Bảng metadata bộ dữ liệu (Mới)

Đây là tính năng chính của bản release v5.1.0. Bộ dữ liệu nay xuất kèm một bảng/đối tượng metadata một dòng mô tả phiên bản đang được cài đặt, giúp ứng dụng phát hiện phiên bản hiện tại và biết khi nào có bản cập nhật mới.

### Thay đổi cấu trúc (schema)

Bảng `vn_provinces_metadata` được thêm vào các tệp schema `*_CreateTables_*` trên cả 4 hệ quản trị cơ sở dữ liệu quan hệ:

| Cột | Kiểu dữ liệu | Ý nghĩa |
|-----|--------------|---------|
| `dataset_version` | `varchar(50)` | Phiên bản dataset (ví dụ `v5.1.0`) |
| `latest_decree` | `varchar(100)` | Nghị định mới nhất đã phản ánh trong dữ liệu (ví dụ `36/2026/QH16`) |
| `generated_at` | `timestamp` | Thời điểm tạo dataset (UTC) |

### Dữ liệu metadata trên tất cả các định dạng

| Định dạng | Tệp / đối tượng metadata |
|-----------|--------------------------|
| PostgreSQL | Bảng `vn_provinces_metadata` trong `postgresql/postgres_ImportData_vn_units.sql` |
| MySQL / MariaDB | Bảng `vn_provinces_metadata` trong `mysql/mysql_ImportData_vn_units.sql` |
| Microsoft SQL Server | Bảng `vn_provinces_metadata` trong `sqlserver/mssql_ImportData_vn_units.sql` |
| Oracle | Bảng `vn_provinces_metadata` trong `oracle/oracle_ImportData_vn_units.sql` |
| JSON | `json/vn_provinces_metadata.json` |
| MongoDB | `mongodb/mongo_data_vn_provinces_metadata.json` (collection `vn_provinces_metadata`) |
| Redis | Hash `vnProvincesMetadata` trong `redis/redis_vn_provinces_dataset.redis` |
| Elasticsearch | `elasticsearch/vn_provinces_metadata.ndjson` + mapping `elasticsearch/mappings/vn_provinces_metadata.json` (index `vn_provinces_metadata`) |

### Dữ liệu mẫu

| dataset_version | latest_decree | generated_at |
|-----------------|---------------|--------------|
| `v5.1.0` | `36/2026/QH16` | `2026-09-12 07:42:08` (UTC) |

```sql
SELECT dataset_version, latest_decree, generated_at FROM vn_provinces_metadata;
```

## 🏙️ Quảng Ninh trở thành thành phố (Mới)

| Trường | Trước | Sau |
|--------|-------|-----|
| `full_name` | Tỉnh Quảng Ninh | Thành phố Quảng Ninh |
| `full_name_en` | Quang Ninh Province | Quang Ninh City |

Mã tỉnh (`22`) và tên (`Quảng Ninh`) không thay đổi. Không có thêm / xóa / thay đổi bản ghi tỉnh, xã nào khác.

**English version**:

This v5.1.0 release adds the `vn_provinces_metadata` table (dataset version, latest decree, generation timestamp) to every dataset format so applications can detect the installed version, promotes Quảng Ninh to a city under Resolution 36/2026/QH16, and removes leftover duplicate files.

## ✨ Dataset Metadata Table (New)

This is the headline feature of the v5.1.0 release. The dataset now ships with a single-row metadata table/object describing the installed release, letting applications detect the current version and know when an update is available.

### Schema changes

The `vn_provinces_metadata` table was added to the `*_CreateTables_*` schema files across all 4 relational database engines:

| Column | Data type | Meaning |
|--------|-----------|---------|
| `dataset_version` | `varchar(50)` | Dataset release version (e.g. `v5.1.0`) |
| `latest_decree` | `varchar(100)` | Latest government decree reflected in the data (e.g. `36/2026/QH16`) |
| `generated_at` | `timestamp` | Dataset generation timestamp (UTC) |

### Metadata across all formats

| Format | Metadata file / object |
|--------|------------------------|
| PostgreSQL | `vn_provinces_metadata` table in `postgresql/postgres_ImportData_vn_units.sql` |
| MySQL / MariaDB | `vn_provinces_metadata` table in `mysql/mysql_ImportData_vn_units.sql` |
| Microsoft SQL Server | `vn_provinces_metadata` table in `sqlserver/mssql_ImportData_vn_units.sql` |
| Oracle | `vn_provinces_metadata` table in `oracle/oracle_ImportData_vn_units.sql` |
| JSON | `json/vn_provinces_metadata.json` |
| MongoDB | `mongodb/mongo_data_vn_provinces_metadata.json` (`vn_provinces_metadata` collection) |
| Redis | `vnProvincesMetadata` hash in `redis/redis_vn_provinces_dataset.redis` |
| Elasticsearch | `elasticsearch/vn_provinces_metadata.ndjson` + mapping `elasticsearch/mappings/vn_provinces_metadata.json` (`vn_provinces_metadata` index) |

### Data example

| dataset_version | latest_decree | generated_at |
|-----------------|---------------|--------------|
| `v5.1.0` | `36/2026/QH16` | `2026-09-12 07:42:08` (UTC) |

```sql
SELECT dataset_version, latest_decree, generated_at FROM vn_provinces_metadata;
```

📖 For format-specific setup and usage instructions, see the corresponding README (`postgresql/`, `mysql/`, `sqlserver/`, `oracle/`, `mongodb/`, `redis/`, `elasticsearch/`, `json/`).

## 🏙️ Quảng Ninh Becomes a City (New)

Under Resolution **36/2026/QH16** (issued 24/08/2026, effective 01/09/2026), Quảng Ninh province was promoted to **Quảng Ninh City**, a centrally-governed municipality. The administrative unit information was updated across all formats:

| Field | Before | After |
|-------|--------|-------|
| `full_name` | Tỉnh Quảng Ninh | Thành phố Quảng Ninh |
| `full_name_en` | Quang Ninh Province | Quang Ninh City |
| `administrative_unit_id` | 2 (Province) | 1 (Municipality) |

The province code (`22`) and name (`Quảng Ninh`) are unchanged. No other province or ward records were added, removed, or changed.

## ⬆️ Upgrading to v5.1.0

**Users upgrading from v5.0.0 (or earlier):** run the patch file [`patch/v5.1.0/v5.1.0_patch.sql`](../../patch/v5.1.0/v5.1.0_patch.sql) on an existing PostgreSQL database. The patch will:

- Promote the Quảng Ninh province row (`code = '22'`) to Quảng Ninh City.
- Create the `vn_provinces_metadata` table and seed it with `v5.1.0` / `36/2026/QH16`.

> The patch targets **PostgreSQL** only; GIS data is not covered.
